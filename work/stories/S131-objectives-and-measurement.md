# S131 — Objectives and measurement

## Identity

- Parent feature: `F066` Service levels and error budgets
- Owner: platform
- Branch: `s131-objectives-and-measurement`
- Decision references: `docs/architecture-decisions.md` sections 1, 3, 9; `docs/capability-contracts.md` row F066

## Vertical slice

As an operator, I want the four promises in spec section 6 written once in `infra/slo/objectives.yml`, turned into Prometheus expressions over F004's existing `http_request_duration_seconds`, and rendered into recording and burn-alert rules that are generated rather than hand-typed, so that "99.5% availability" is a number a query returns and a hand edit to a rule file fails CI.

## Requirements

- **SR-S131-01:** `infra/slo/objectives.yml` parses into the `Objectives` model with `version`, `window: 28d`, `classes`, `objectives`, `burn_alerts`, and `policy`; unknown keys, a target outside `0 < target < 1`, a duplicate objective id, and a class no objective references are each rejected as `slo.schema` with the offending line (covers FR-F066-01).
- **SR-S131-02:** The `classes` map declares `core_read`, `core_write`, `async_ack`, `analytics`, `integration`, and `exempt` with explicit axum route templates and methods, seeded with the M1 routes of F002, F003, F038, and F004; two classes claiming the same `(route, method)` pair fail as `slo.class_overlap`, and a route in the exposition sample belonging to no class fails as `slo.route_unclassified` (FR-F066-02).
- **SR-S131-03:** The four objectives are expressed exactly as specified: `availability_core` as the non-5xx ratio over `core_read` and `core_write` at 0.995, `latency_core_read` on `le="0.5"` at 0.95, `latency_core_write` on `le="0.8"` at 0.95, and `ack_async` on `status="202"` and `le="2"` at 0.99, with analytics and integration traffic absent from every numerator and denominator (FR-F066-03, FR-F066-04, FR-F066-05, FR-F066-06).
- **SR-S131-04:** Budget arithmetic over the rolling 28-day window is implemented and unit-tested: 40,320 minutes in the window, 201.6 budget minutes for `availability_core`, 2,016 for each latency objective, 403.2 for `ack_async`, with `slo:budget:remaining_ratio28d` and `slo:budget:remaining_minutes28d` recorded per objective and the remaining ratio clamped at -1 for display only (FR-F066-07).
- **SR-S131-05:** `render_recording_rules` emits `slo:sli:ratio_rate<w>` and `slo:burn_rate:ratio_rate<w>` for the eight windows `5m, 30m, 1h, 2h, 6h, 24h, 3d, 28d` with class attribution expanded into `route=~` and `method=~` alternations and `label_replace` stamping `class`, so F004's exporter label set is unchanged; every rule aggregates with `sum by (objective)` and keeps no `route` label (FR-F066-08, NFR-F066-01).
- **SR-S131-06:** `render_burn_alerts` emits the four window pairs with factors computed as `consumed * 672 / long_hours` — 13.44, 5.6, 2.8, and 0.93 — never as literals in the source, and `verify-slo` reports `slo.rule_drift` and `slo.threshold_drift` with expected and found values when either generated file differs from the committed one (FR-F066-08, FR-F066-09).
- **SR-S131-07:** `check_exposition` parses a recorded Prometheus text exposition and fails with `slo.bucket_missing` naming the objective and boundary when `http_request_duration_seconds_bucket` lacks an exact `le` series for 0.5, 0.8, or 2, or when the metric is not a histogram, and prints `skipped: metrics sample absent` and passes when no sample is supplied (FR-F066-12).
- **SR-S131-08:** Nothing in this slice reads a database, opens a socket, or writes outside `infra/slo/`, `infra/prometheus/rules/`, and `infra/alerts/burn-rate.yml`; the objectives file and generated rules contain no tenant id, user id, or payload, only route templates, methods, status classes, and ratios (NFR-F066-02).
