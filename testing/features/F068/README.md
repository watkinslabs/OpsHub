# F068 — Persistence layer and data access classes harness

Feature-gated tests for `F068`. Keep test code in this directory.

- Gate: `F068_FEATURE`
- Targeted: `cargo xtask test-feature F068`
- Full: `cargo xtask test-all`
- What is proved here: that the sealed `Repository` contract in `crates/persistence` applies the tenant predicate, the soft-delete filter, the optimistic version check, the audit row, and the outbox row on every path; that `UnitOfWork` keeps one transaction across several repositories; that keyset pagination over the F028 signed cursor cannot be replayed across tenants or filters; and that `cargo xtask check-persistence` fails a build carrying SQL, a pool type, an unmapped or doubly-written table, an array column, or an unlisted `jsonb` column. What is not proved here: the pool builder, the `outbox_events` publisher, the `audit_events` schema, and the `users` migration, which belong to F004, F003, and F002.
- Two ways of proving, deliberately split. Rules that a type can enforce are proved with `trybuild` compile-fail cases in `api/ui/` and never reach a database: a hand-written `impl Repository`, a specification returning SQL text, a `Column` from a foreign specification, two live handles on one `UnitOfWork`, use after `commit`, and a `PurgeCtx` without a `PurgeGrant`. Rules a type cannot enforce are proved at runtime against a throwaway PostgreSQL 18 for every registered specification, not for a sample.
- Fixtures: `testing/fixtures/persistence/seed.rs` (tenants A and B, 3 and 100,000 users, fixed UUIDv7 sequence, fixed clock `2026-09-03T00:00:00Z`, fixed cursor HMAC key), `trees/{clean,raw_sql,connection_leak,escape_hatch,double_write,unmapped_table}/` source trees for the static gate rules, `migrations/{arrays,jsonb_listed,jsonb_unlisted,stale_policy}/*.sql`, `catalog/{matching,missing_table}.md` catalog excerpts, and `baseline.json`.
- Database isolation: one `postgres:18` container per test session, database `opshub_f068_w{worker}` per worker, F002 `*_tenants_*.sql`, F003 `*_authz_*.sql`, and F004 `*_runtime_*.sql` applied at setup and dropped at teardown, one tenant id per test. A session that cannot reach Docker fails the database lane rather than skipping it.
- Lanes: `requirements/` (traceability for every FR-F068 and NFR-F068 id), `api/` (compile-fail cases and connection-free unit cases), `database/` (the runtime rules and the per-specification conformance suite), `frontend/` and the HTTP half of `api/` (negative controls — this feature owns no route and no component), `e2e/` (the gate over fixture trees and the crate over a real database, no browser), `accessibility/` (gate output and the crate README), `performance/` (gate runtime and pagination cost). Each `cases.md` lists the test names in that lane and the requirement ids they prove.
- Evidence: `testing/evidence/F068/` holding the gate JSON, the `trybuild` expectations, the conformance matrix with one row per registered specification, and the pagination timings.
